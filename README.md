# Circuit Data Analyzer (CDA) v0.2 — MVP

サーキット走行データ解析アプリ。**index.html 単体で動作**します（インストール不要・依存ライブラリなし）。
データは端末内だけで処理され、外部へ送信されません。

---

## 使い方

### PC — インストール不要
`index.html` を**ダブルクリック**するだけです。インストーラも管理者権限も不要、Node.jsやPythonも要りません。
既定のブラウザで開いたら CSV / ZIP をドロップしてください。

推奨ブラウザは **Chrome / Edge / Firefox**。Internet Explorer は非対応です。

> ファイルを直接開いた場合（`file://`）、ブラウザの制約で「最近のセッション」の保存が効かないこと
> があります（Chrome/Edge）。解析機能とメモの保存には影響しません。毎回この履歴を使いたい場合は、
> 公開URL版を使うか、簡易サーバー経由で開いてください。

### スマホ
公開URLを開く → 画面をタップしてファイルを選択。
一度読み込んだセッションは端末内（IndexedDB）に保存され、次回は「最近のセッション」から即座に開けます。

---

### 別日のデータを重ねて比較する

1. まず基準にする日を「読込」で開く
2. ヘッダーの **＋比較** を押して、別日のCSV/ZIPを読み込む
3. 上部にセッションチップ（`8/23` `8/24`）が出て、ラップ表が日ごとに分かれます
4. 両日のラップを選ぶと、同じコース距離軸で重なります。**Δタイムの基準ラップは別日のラップでも選べます**（Rボタン）

別日のZIPを**同時にドロップ**しても同じ結果になります。チップの `×` で比較データを外せます。

> **重要**：コース形状（中心線）は**最初に読み込んだ日**から作られ、以降の日はその中心線に投影されます。
> これにより距離軸が完全に一致します。基準日はチップの左端（`×`が付かない方）です。
> 別コースのデータを追加しようとすると、投影が破綻するため読み込みを拒否します。

### 動画を同期して見る

ヘッダーの **動画** ボタンで動画パネルを開きます。

| 動画ソース | `index.html`をダブルクリック<br>(file://) | **CDAを起動.bat**<br>(localhost) | スマホ（公開URL） |
|---|---|---|---|
| ローカル動画ファイル（MP4/MOV/WebM等） | ○ | ○ | ○ |
| YouTube（動画URL / プレイリストURL） | **×** | **○** | **×** |

> **YouTubeを使う場合は必ず `CDAを起動.bat` から開いてください。**
> ファイルを直接開いた状態（`file://`）では、YouTube側が埋め込み再生を拒否します
> （ページに正規のオリジンが無いため）。これはアプリ側では回避できません。
> `.bat` は `http://localhost:8123` でこのフォルダを配信してブラウザを開くだけのもので、
> 外部へは公開されません（`127.0.0.1` に限定）。小さなサーバー用ウィンドウが残るので、
> 終了時は閉じてください。Pythonが無い場合は自動的に通常の起動に切り替わります。
>
> 公開URL版（スマホ）は外部サーバーへの通信自体が遮断されるため、YouTubeは利用できません。
> スマホで動画同期を使う場合は「動画ファイルを選ぶ」方式をご利用ください。

**合わせ方**

1. 動画を読み込む（「動画ファイルを選ぶ」または YouTube URL を貼って「読込」）
2. 動画で分かりやすい瞬間（S/Fライン通過など）を表示する
3. グラフ側のカーソルを同じ地点に合わせる
4. **「ここで同期」** を押す

以降は双方向に連動します。カーソルを動かせば動画がシークし、動画を再生すればカーソルとラップが
自動追従します（ラップをまたぐと表示ラップも自動で切り替わります）。「連動」ボタンで一時停止できます。

**複数本に分割された動画**

プレイリストURLを貼ると各動画がチップ（`1` `2` `3`…）として並びます。**1本ずつ「ここで同期」**
してください。`●` が同期済み、`○` が未同期です。カーソル位置に応じて該当する動画へ自動で切り替わります。

> 動画ごとに基準時刻を持つ設計なので、長時間レースでカメラの時計がGPSからズレていっても、
> 各動画を合わせるたびにリセットされます。

**注意**

- YouTubeのシーク精度は±0.1〜0.5秒程度で、コマ単位ではありません。ローカル動画の方が高精度です。
- YouTubeの同期設定（動画IDと基準時刻）は端末に保存され、次回「前回のYouTube同期設定を復元」で戻せます。
  ローカル動画ファイルはブラウザの仕様上パスを保持できないため、毎回選び直しが必要です。

### 公式コースマップを重ねる

Setupタブの **公式コースマップ → コースデータを読み込む** から、お手持ちのコースデータを読み込むと、
実測復元の路面に代えて**公式のコース形状**の上に走行ラインを描きます。

| 対応形式 | 内容 |
|---|---|
| デジスパイス `cd_*.pth` | コース形状（`<path>` ブロックの `経度,緯度` 列）。**主データ** |
| Qstarz `XXX-YYY.bin` | コース名とスタートラインの緯度経度・方位 |
| Qstarz `XXX-YYY.bin`（148B超） | 追加の12バイト記録＝**スプリット（セクター）ライン**。読み込むと自動でセクター設定 |
| Qstarz `.map` | コースのラスタ画像（152×200のRLE）。**座標情報が形式内に一切無い**ため未使用 |

#### なぜ形状はデジスパイス側を使うのか

Qstarzの `.bin` は148バイト全体を解析した結果、**名前(128B) + 種別"TRA" + float32×3（緯度・経度・方位）だけ**で、
バウンディングボックスも縮尺も含まれていません。`.map` は 152×200 のラスタ画像（BT-1000GTの画面用と思われる）で、
これも座標を持ちません。つまり **Qstarz側のデータだけでは地図上に配置できません**。

一方 `.pth` は緯度経度そのものなので直接重ねられます。そのため
**形状 = デジスパイス、コース名とスタートライン・セクター = Qstarz** という役割分担にしています
（Qstarzを使っていないわけではありません）。

**ZIPのまま**選べます（`DS3_1.zip` や `TrackMap6KS.zip` をそのままでOK）。
収録されている全コースから、**読み込み済みセッションに最も近いコースを自動選択**します。
5km以上離れたコースしか無い場合は「別コースのデータでは？」と警告して読み込みません。

位置が合わない場合はSetupタブの **位置微調整**（東西/南北, m単位）でずらせます。

> **コースデータは同梱していません。** 各自がお持ちのデータを読み込む方式です
> （要件定義書3.8「特定メーカーのデータをそのまま再配布する設計にはしない」に沿っています）。
> 読み込んだ内容はこの端末にのみ保存され、外部へは送信されません。

#### 0823美浜データでの検証結果

| 検証 | 結果 |
|---|---|
| 95コースから自動選択 | `mihama_premium` を **162 ms** で特定 |
| ベストラップが公式コース面に収まる割合 | **95.89%**（補正なし） |

### GitHub等に置いたデータを一覧から開く

アプリと同じ場所に `data/manifest.json` を置くと、起動画面にセッション一覧が出て、
クリックだけで読み込めます。`data/manifest.example.json` を雛形として同梱しています。

```json
{
  "title": "K4GP 走行データ",
  "track": ["data/DS3_1.zip"],
  "sessions": [
    { "name": "美浜 レインボーカラーズ耐久", "date": "2026-08-23",
      "auto": true, "files": ["data/0823美浜耐久_CSV一式.zip"] }
  ]
}
```

- `"auto": true` … 起動時に自動で読み込み
- `?s=1` / `?s=美浜` … URLでセッションを指定して開く
- `"track"` … コースデータも一緒に自動読み込み

| 開き方 | 一覧が使えるか |
|---|---|
| GitHub Pages | ○ |
| CDAを起動.bat（localhost） | ○ |
| index.html をダブルクリック（file://） | **×**（ブラウザがfetchを禁止するため） |
| claude.ai 公開URL | **×**（外部通信が遮断されるため） |

> **公開リポジトリに置いたファイルは誰でもダウンロードできます。** GPSログを公開したくない場合は、
> 非公開リポジトリ＋Cloudflare Pages / Netlify をご検討ください。
> また、メーカー製コースデータ（`.pth` / `.bin`）を公開リポジトリに置くのは再配布にあたります。

### ドライバー名と凡例

Setupタブの **ドライバー（スティント）** で、ラップ範囲にドライバー名を割り当てます。
耐久のドライバー交代に合わせて「1〜80 田中」「81〜160 佐藤」のように登録すれば、

- グラフ・マップ上の**凡例**に `L7 田中  55.765` のように色と対応して表示
- ラップ表のラップ番号の横にドライバー名
- Δタイムの見出しが `Δ TIME vs Lap 7 田中`
- パワポ出力・CSV出力にもドライバー名が入る

「選択中のラップから範囲を入れる」を押すと、選択中のラップから開始・終了が自動入力されます。
凡例は同じくSetupタブでオフにできます。

### 報告用の出力（パワポ / 画像）

Setupタブの **凡例 / 出力** から、選択中のラップを対象に書き出します。

**パワポ(.pptx)で出力** … 5枚のスライドを生成します。

| スライド | 内容 |
|---|---|
| 1 | 表紙（コース・日付・ベストラップ・ドライバー・車両・天候） |
| 2 | 走行ライン（マップ画像）＋ 凡例 |
| 3 | チャンネル比較グラフ（コース距離軸） |
| 4 | ラップ比較表（ドライバー / タイム / Δベスト / 最高速 / 最大横G / セクター） |
| 5 | 気づき・メモ＋マーカー一覧 |

16:9で、画像は画面より高解像度で描き直してから貼り付けるためスライドでもぼやけません。
PowerPointで開いた後は、通常のスライドとして自由に編集できます。

**画像(PNG)で出力** … マップとグラフを高解像度PNGで書き出します。既存の資料に貼るときに便利です。

> .pptxはアプリ内で生成しています（外部サービスへの送信は一切ありません）。
> 生成物は `python-pptx` で検証済みです（`node test_pptx.mjs` で再検証できます）。

## 検証済みのデータ仕様（0823美浜耐久で実測確認）

Qstarz **BL-1000GT** / QRacing PC 出力、**10 Hz 厳密**（5.29時間・欠測ゼロ）。

| 列 | 単位（実測で確定） | 備考 |
|---|---|---|
| `time` + `ms` | UNIX秒 + ミリ秒 | 10 Hz。`datetime_JST`はms欠落のため未使用 |
| `lat` / `lon` / `altitude` | deg / deg / m | |
| `speed` | **km/h** | GPS経路長910.6m・速度積分901.7m・`distance`列911.2mの三者一致で確定 |
| `distance` | **km**（セッション累積） | 0 → 210.6 km |
| `Gx` | **前後G**（+ = 加速） | d(speed)/dt との相関 **+0.64** で判定 |
| `Gy` | **横G**（+ = 左） | ヨーレート×速度との相関 **−0.87** で判定 |
| `Gz` | 上下G | 静止時 ≈ 1.0（重力込み。既定で1G減算） |
| `AccDec` / `Inclination` | — | **全行 0**（未使用列） |
| `tilt` / `lean` | — | **全行 定数**（内部値・無意味） |
| ジャイロ | **列が存在しない** | ヨーレートは GPS方位の微分から生成 |

> **ヨーレートについて**：このロガーのCSVにはジャイロ列がありません。本アプリは
> heading（GPS方位）を時間微分して deg/s を生成しています。低速時の方位ノイズによる
> 偽スパイクを避けるため 8 km/h 以下では0とし、±200 deg/s でクランプしています。
> センサー実測値ではないので、絶対値の精密比較には使わないでください。

> **セクターについて**：`03_Split.csv` は1ラップ1区間しか持たず、**セクター定義がありません**。
> Setupタブで任意の距離に区切れます（既定はコース長の1/3・2/3）。

## 画面

- **上部KPI**：コース / ラップ / ラップタイム / ベスト / Δタイム / 現在位置 / 速度 / 前後G / 横G / ヨー / セクター
- **Track Map**：コース形状、走行ライン、S/F・セクター線、現在位置（ラップ色別）
- **グラフ**：Speed / 前後G / 横G / 上下G / ヨーレート / Δタイム を**共通のTrack Distance軸**で縦積み
- **セッションチップ**：複数日を読み込むと上部に表示。`×` で比較データを外す
- **Laps**：全ラップ一覧（日ごとに区切り表示、ベスト紫、異常ラップ除外、最大8ラップ同時表示、Rボタンで基準ラップ）
- **Channels**：グラフ段の増減（チャンネルを増やせば段が増える設計）
- **Notes**：セッションメモ / ラップ別メモ / 現在位置マーカー、JSON・CSV書き出し
- **Setup**：G符号反転、重力減算、平滑化、セクター編集、コントロールライン設定、車両・ドライバー情報

## 設計上の要点

- **Track Distance（コース距離）が全データの共通軸**。時間軸ではないため、異なるラップ・
  異なるドライバーを同一コース位置で比較できます。
- GPS座標はそのまま使わず、ベストラップから生成した1m間隔の中心線へ投影して
  `track_distance` と `lateral_offset` に変換しています。
- **公式コースマップを読み込んでいない場合、マップに描かれる「コース」は公式データではありません。** サーキットの測量データは
  GPSログには含まれないため、読み込んだ全有効ラップから復元しています。1mごとの地点で
  横方向オフセットの2〜98パーセンタイルを取り、「実際に走られた路面」を描いています
  （外れ値1点で道幅が膨らまないようパーセンタイルを使用）。
  したがって、誰も使わなかった幅（エスケープゾーン、使っていない側の縁石など）は描かれません。
  逆にラインが帯からはみ出して見える場合、それは**普段の走行ラインから外れて走った**ことを示します
  （オーバーテイク、コースオフ、GPS誤差など）。
- ラップ検出は「スタート地点から○m以内」ではなく、**コントロールラインの通過＋進行方向**
  （進行方向とライン方向の内積 > 0.5）で判定します。
- 欠損値は0に変換せず NaN のまま保持します（センサー欠損を「完全に安定」と誤読させないため）。
- 内部データモデルはQstarz専用ではありません。チャンネルを追加すればグラフ段が増えます。
